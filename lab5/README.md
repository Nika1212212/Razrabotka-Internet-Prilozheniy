# ЛР №5. AJAX-запросы к API (только фронтенд)

Продолжение ЛР3. Код бэкенда ЛР4 в эту папку **не входит**: сервер ЛР4 запускается отдельно и остаётся в своей ветке/папке. Здесь находятся только страницы, компоненты и слой запросов к API.

Реализован **вариант 1** дополнительных материалов: отдельный компонент фильтрации по `title` через query-параметр GET-запроса и удаление карточки через DELETE на странице конкретной карточки по ID.

Отчёт по работе: [Отчет по ЛР5 Горбунова ИБМ3-54Б.pdf](./Отчет%20по%20ЛР5%20Горбунова%20ИБМ3-54Б.pdf) (титульник скопирован с отчёта по ЛР4, 6 страниц).

## Картинки

Флаги лежат локально в `lab5/images/*.svg` — внешний сервис flagcdn.com не используется, поэтому изображения отображаются без доступа в интернет. Если API вернёт внешнюю ссылку, которая не загрузится, компоненты подставят `images/placeholder.svg` через обработчик `onerror`.

## Запуск

1. Запустить бэкенд ЛР4: в его папке `npm start` — API доступно на `http://localhost:3000`.
2. Открыть `lab5/index.html` через VS Code **Live Server** (порт, например, 5501). Порт фронтенда обязан отличаться от 3000 — именно это создаёт запрос с другого origin и делает демонстрацию CORS наглядной.
3. Включить расширение Chrome **CORS Unblock** (после показа ошибки). Для сложных POST/PATCH-запросов с `Content-Type: application/json` в настройках расширения включить `Overwrite 4xx status codes with 200` и `Access-Control-Request-Headers`, затем нажать Start/Restart.

> Если бэкенд ЛР4 уже отдаёт заголовок `Access-Control-Allow-Origin` (например, подключён middleware `cors()`), ошибки CORS не возникнет. Чтобы показать ошибку на демонстрации, временно запустите сервер без CORS-заголовков (или отключите `app.use(cors())` в коде ЛР4); в ЛР5 код бэкенда не трогаем — только фронтенд.

## Адресная строка

Переходы между «вкладками» приложения меняют URL через **History API** (`pushState`), без перезагрузки страницы. Кнопки браузера «Назад/Вперёд» работают через событие `popstate`.

| Что открыто | Адрес |
|---|---|
| Главная | `index.html` |
| Главная с фильтром | `index.html?title=Турция` |
| Карточка заявки | `index.html?view=product&id=1` |
| Добавление заявки | `index.html?view=form` |
| Редактирование заявки | `index.html?view=form&id=1` |

Фильтр тоже пишется в адресную строку, поэтому его можно скопировать как ссылку и восстановить кнопкой «Назад».

## Порядок показа

1. Chrome → DevTools → **Network** → фильтр **XHR**.
2. В поле «Фильтр по названию» ввести название (например, `Турция`) и нажать «Применить» (или Enter). С выключенным CORS Unblock в консоли будет ошибка CORS, в Network запрос красный, статус 0.
3. Включить CORS Unblock, повторить фильтрацию: запрос `GET /visas?title=...` выполняется успешно; во вкладке **Headers** запроса видно query-параметр `title` (в URL и в списке Query String Parameters).
4. В Postman выполнить `POST http://localhost:3000/visas` с JSON (например, `{"src":"https://flagcdn.com/w320/fr.png","title":"Франция","text":"Шенгенская виза","price":9200,"visaType":"schengen"}`). Обновить страницу приложения — новая карточка появилась. Ввести её название в фильтр — приложение покажет только её (запрос уйдёт с `?title=Франция`).
5. Кнопка «Подробнее» открывает страницу карточки по ID — адресная строка становится `?view=product&id=1`; на ней есть кнопка «Удалить», которая выполняет `DELETE /visas/:id` и возвращает на главную (вариант 1 доп. материалов).
6. Кнопка «+ Добавить новую заявку» открывает форму с пустыми полями (`?view=form`); кнопка «Изменить» на карточке открывает ту же форму с заполненными полями (`?view=form&id=1`). Кнопки «Сохранить» в ЛР5 нет — поля редактируемые, но сохранить данные нельзя (это появится в ЛР6). Кнопка браузера «Назад» возвращает на предыдущую страницу приложения.

## Контрольные вопросы

### Проблема CORS и пути решения

CORS (Cross-Origin Resource Sharing) — механизм браузера, который не пускает скрипт страницы с origin `http://127.0.0.1:5501` читать ответ с другого origin `http://localhost:3000` (различается порт — уже другой origin). Запрос может уйти на сервер, но браузер блокирует выдачу ответа JavaScript, если в ответе нет заголовка `Access-Control-Allow-Origin`. В консоли появляется сообщение `Access to XMLHttpRequest ... has been blocked by CORS policy`, а в Network у запроса статус 0.

Простой запрос (GET, HEAD, POST с `text/plain`, `application/x-www-form-urlencoded`, `multipart/form-data`) уходит сразу. Сложный запрос, например POST/PATCH с `Content-Type: application/json`, сначала отправляет предварительный `OPTIONS`-запрос (preflight); сервер должен разрешить метод и заголовки (`Access-Control-Allow-Methods`, `Access-Control-Allow-Headers`).

Пути решения:
1. Разместить фронтенд на том же домене и порту, что и API (тогда origin совпадает).
2. Правильно настроить CORS на сервере: отдавать `Access-Control-Allow-Origin` (для конкретного source или `*`), разрешённые методы и заголовки, обрабатывать `OPTIONS`. Это правильный вариант для продакшена.
3. Для локальной разработки — расширение браузера CORS Unblock: оно перехватывает запрос/ответ и подменяет заголовки, «убеждая» браузер, что ответ разрешён. Быстро, но обходит встроенную защиту браузера, поэтому в продакшене так делать нельзя.

### Что такое AJAX и XHR

AJAX (Asynchronous JavaScript and XML) — подход, при котором страница обменивается с сервером асинхронно без полной перезагрузки: JavaScript отправляет запрос, получает данные и обновляет нужную часть DOM.

XMLHttpRequest (XHR) — встроенный в браузер объект, который и выполняет такой HTTP-запрос. Несмотря на «XML» в названии, он передаёт любые данные (чаще JSON). Типичный цикл: `new XMLHttpRequest()` → `open(method, url)` → (для JSON) `setRequestHeader('Content-Type', 'application/json')` → `send(body)` → обработка `onreadystatechange` при `readyState === 4`, разбор `responseText` и проверка `status`. В ЛР5 все обращения к API (список, фильтрация, карточка по ID, удаление) сделаны именно через XHR в модуле `modules/ajax.js`; `fetch` не используется.
